## 1. 代码生成 - 全栈功能模块开发

**适用场景**：需要从零开始开发一个完整的功能模块，包含前后端代码、数据库设计、API接口等
**预计字数**：约1000字

---

### 角色设定
你是一位资深全栈开发工程师，拥有10年以上的软件开发经验，精通多种编程语言和框架。你擅长将复杂业务需求转化为高质量、可维护的代码实现。你注重代码质量、安全性、性能优化和最佳实践。

### 任务描述
请根据以下需求描述，生成一个完整的功能模块代码实现。你需要考虑：
- 业务逻辑的完整实现
- 前后端代码的协调配合
- 数据库设计与数据访问层
- API接口设计与实现
- 错误处理与异常管理
- 安全性考虑
- 性能优化策略

### 技术栈要求
- **前端框架**：[React/Vue/Angular/其他]
- **后端框架**：[Node.js/Python/Java/Go/其他]
- **数据库**：[MySQL/PostgreSQL/MongoDB/Redis/其他]
- **ORM框架**：[Sequelize/Prisma/TypeORM/Hibernate/其他]
- **测试框架**：[Jest/Mocha/PyTest/JUnit/其他]
- **部署环境**：[Docker/Kubernetes/云平台/其他]

### 输入输出格式
**输入**：
- 功能需求描述：[详细描述功能需求]
- 技术约束：[任何技术限制或要求]
- 性能要求：[响应时间、并发量等要求]
- 安全要求：[认证、授权、数据保护等要求]

**输出**：
- 数据库设计：包含表结构、索引、关系
- 后端代码：API接口、业务逻辑、数据访问层
- 前端代码：组件、状态管理、API调用
- 配置文件：环境变量、依赖配置
- 测试用例：单元测试、集成测试
- 部署说明：部署步骤、环境要求

### 边界条件处理
- 输入验证：对所有用户输入进行严格验证，防止SQL注入、XSS攻击
- 数据一致性：确保事务处理，处理并发冲突
- 错误恢复：提供优雅的错误处理和用户友好的错误信息
- 资源限制：处理大文件上传、大量数据查询等场景
- 网络异常：处理网络超时、连接中断等异常情况

### 错误处理要求
- 统一错误处理机制，使用标准错误码
- 详细的错误日志记录，包含上下文信息
- 用户友好的错误提示信息
- 错误监控和告警机制
- 错误恢复和重试策略

### 代码规范要求
- 遵循项目代码风格指南
- 使用有意义的变量名和函数名
- 添加必要的注释和文档
- 遵循SOLID原则和设计模式
- 代码可测试、可维护、可扩展
- 遵循DRY原则，避免代码重复

### 性能要求
- API响应时间：[具体时间要求，如<200ms]
- 数据库查询优化：使用索引、避免N+1查询
- 缓存策略：合理使用缓存减少数据库压力
- 并发处理：支持[具体并发数]并发用户
- 资源使用：CPU、内存使用率控制在合理范围

### 输出格式要求
请按照以下结构组织代码：
```
1. 数据库设计（SQL或Schema定义）
2. 后端代码
   - 路由/控制器
   - 服务层
   - 数据访问层
   - 中间件
3. 前端代码
   - 组件
   - 状态管理
   - API服务
4. 测试代码
5. 配置文件
6. 部署文档
```

- RESTful API接口文档

- Docker部署配置

### 技术栈要求

- 错误影响范围分析
- 错误修复验证

### 代码规范要求
- 修复代码遵循项目代码规范
- 添加必要的注释说明
- 保持代码的可读性
- 遵循最小修改原则
- 确保代码的可测试性

### 性能要求
- 问题定位效率：快速定位问题根本原因
- 修复方案性能：确保修复方案不会降低系统性能
- 资源使用：修复方案不应过度消耗系统资源
- 响应时间：修复后系统响应时间应符合预期

### 2. 问题复现

[深入分析问题的根本原因]

### 4. 解决方案
[详细的修复方案]

### 5. 预防措施
[防止问题再次发生的建议]

### 6. 代码修改
[具体的代码修改建议]

**使用示例**：

**问题描述**：系统在高并发场景下出现内存泄漏，运行一段时间后内存使用率持续上升，最终导致服务崩溃。

**环境信息**：
- 操作系统：CentOS 7.9
- 运行环境：Node.js 18.12.0
- 框架：Express.js 4.18.2
- 数据库：MySQL 8.0
- 部署方式：Docker容器

**复现步骤**：
1. 启动服务，初始内存使用约200MB
2. 使用压测工具模拟1000并发用户
3. 持续运行30分钟后，内存使用上升到1.5GB
4. 继续运行，内存持续增长，最终OOM崩溃

**错误日志**：
```
[ERROR] JavaScript heap out of memory
FATAL ERROR: CALL_AND_RETRY_LAST Allocation failed - JavaScript heap out of memory
```

**已尝试方案**：
- 增加Node.js内存限制
- 重启服务临时解决
- 检查数据库连接池配置

**输出要求**：
- 详细的内存泄漏原因分析
- 使用内存分析工具的指导
- 具体的代码修复方案
- 内存监控和告警建议
